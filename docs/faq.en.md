# NetLedger Frequently Asked Questions

## Installation & Initialization

### Q: "Access Denied" error when running Init
**A**: You must run PowerShell as Administrator. Right-click PowerShell → "Run as Administrator".

### Q: Sysmon download fails with network error
**A**: Possible causes:
1. Firewall blocks access to `live.sysinternals.com`
2. Proxy configuration issue
3. Manual fix: Download `Sysmon64.exe` from [Microsoft](https://learn.microsoft.com/sysinternals/downloads/sysmon), place it in `C:\Sysmon\`, then re-run Init

### Q: No log files after initialization
**A**: This is normal. Init only creates directories and scheduled tasks. Log files appear after the first scheduled run (default 00:30 daily) or manual Export.

### Q: Will my existing Sysmon config be overwritten?
**A**: Yes. Init writes its own Sysmon config. Backup your custom rules before running Init, then manually merge afterward.

## Daily Usage

### Q: Daily report shows zero events
**A**: Check the following:
1. Run `-Mode Status` to verify component health
2. Confirm Sysmon service is running (`Get-Service Sysmon64`)
3. Verify audit policies are enabled (`auditpol /get /category:*`)
4. Ensure there was network activity during the collection window

### Q: Chinese characters appear garbled in the report
**A**: Reports use UTF-8 with BOM encoding. Try:
- Open with VS Code (auto-detect encoding)
- In Notepad: File → Save As → select UTF-8 encoding

### Q: Export takes longer than 5 minutes
**A**: Normal execution should take 1-3 minutes. If timeout occurs:
1. Security log volume is high (capped at 50,000 events)
2. Disk I/O is busy
3. Check `run.log` to identify which collection step is slow

### Q: Can I export in CSV format?
**A**: Currently only TXT format is supported. The `$ExportFormat` config option reserves CSV for future versions.

## Alerts

### Q: Many "unusual port" alerts — am I infected?
**A**: Not necessarily. Many legitimate apps use non-standard ports (Steam: 27015-27030, databases: 1433/3306, etc.). Alerts are conservative heuristics; cross-reference with process name and destination IP.

### Q: Suspicious process alert — how to verify?
**A**:
1. Check the full process path in the alert
2. Scan the file on VirusTotal
3. Review the process's historical connection targets
4. If confirmed safe, add the process name to the whitelist in `Test-SuspiciousProcess`

### Q: Why are DNS failures flagged as "DGA domains"?
**A**: DGA (Domain Generation Algorithm) domains are randomly generated by malware. Not all DNS failures are DGA — temporary network issues can also cause failures. Only be concerned with persistent failures on domains that look random (e.g., `xk3j9f8a2b.com`).

## Performance & Storage

### Q: How much disk space do logs use?
**A**: Daily log file size depends on network activity:
- Typical office PC: 0.5-2 MB/day
- Heavy development/download: 2-10 MB/day
- 90-day retention: approximately 45 MB - 900 MB

### Q: Does the script consume CPU during collection?
**A**: Export causes brief CPU usage (mainly `Get-WinEvent` queries). The scheduled task runs at 00:30, so there's no impact on daily use.

### Q: How to change log retention period?
**A**: Edit `$RetentionDays` in `NetworkMonitor.ps1` (e.g., set to 30), save, and it takes effect on the next Export run.

## Uninstall

### Q: Audit policies not fully disabled after uninstall
**A**: The uninstall script attempts to disable them, but group policies may override local settings. Check with:
```powershell
auditpol /get /subcategory:"Filtering Platform Connection"
```
If still enabled, manually disable:
```powershell
auditpol /set /subcategory:"Filtering Platform Connection" /success:disable
```

### Q: Sysmon driver remains after uninstall
**A**: The uninstall script runs `Sysmon64.exe -u` to remove the driver. If it fails, rebooting will clean up the driver. You can also manually delete `C:\Windows\Sysmon64.exe` and `C:\Windows\SysmonDrv.sys` if they exist.
